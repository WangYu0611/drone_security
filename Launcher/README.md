# Stage 1 single-screen launcher

For a new workstation follow [First run on Windows](../Docs/First-Run-Windows.md). Install UE 5.8, Cesium for Unreal, VS C++ tools and Python 3.10+ with Tk, then run `SetupDroneSecurity.cmd`. Use `CheckDroneSecurity.cmd` for actionable diagnostics and `DroneSecurityLauncher.cmd` to launch. UE is discovered through the registry/Epic manifest; optional local overrides belong in ignored `Launcher/config.local.json`.

Reviewed against the implementation on 2026-10-30. The launcher opens without starting a session; choose **Launch DEMO (Singapore)** or **Launch Realtime Mode**. `CheckDroneSecurity.cmd` checks installed dependencies, resolved paths, LFS assets and build outputs; it does not verify a Cesium token, provider allowance, live map access or actual video playback. Configure your own Cesium ion connection in the UE editor before expecting online terrain. The default online source is Google Photorealistic 3D Tiles through Cesium ion; this path does not require a separate Google Maps API key. Mock operation needs no physical aircraft connection or video URL.

## Local configuration

`Launcher/config.local.json` merges over `Launcher/config.json`. Only set values that differ on the workstation; keep credentials out of this file and public commits.

| Setting | Default / purpose |
| --- | --- |
| `ue_executable` | Empty means discover UE 5.8; set an absolute `UnrealEditor.exe` path only when discovery fails |
| `backend_executable` | `Backend/build/Release/DroneBackend.exe` |
| `map` | `/Game/Level/CesiumWorld` |
| `http_endpoint`, `ws_endpoint` | DEMO: `http://127.0.0.1:19880`, `ws://127.0.0.1:19881/ws`; newly owned Backends must be local |
| `runtime_directory` | DEMO: `Saved/Stage1`, including existing Mock business data under `data` |
| `startup_timeout` | `180` seconds; increase if first-run shader compilation delays client readiness |
| `max_fps` | `20`, applied to each UE client |
| `auto_start` | `false`; wait for a mode button. Explicit `true` starts `startup_mode` |
| `startup_mode` | `demo`; automatic startup mode when `auto_start=true`; allowed values: `demo`, `realtime` |
| `mock_reset_on_start` | `true`; controls the new owned Mock Backend reset described below |
| `realtime_http_endpoint`, `realtime_ws_endpoint` | Real-time: `http://127.0.0.1:8080`, `ws://127.0.0.1:8081/ws`; match the selected Backend configuration |
| `realtime_backend_config` | `Backend/config.yaml`; existing registry and `port_map` remain authoritative; local override supported |
| `realtime_runtime_directory` | `Saved/Realtime`; launcher ownership records and logs, not a new business database |
| `realtime_gps_timeout` | `60` seconds to obtain a valid GPS fix when a real UAV is connected |
| `realtime_gps_max_age` | `5.0` seconds; maximum age of Backend's packet receipt time |
| `realtime_device_wait` | `8` seconds to discover a connected real UAV before considering computer location |
| `realtime_computer_location_timeout` | `15` seconds for Windows system location when no real UAV is connected |

The launcher does not append `-httpproxy` or support a custom `extra_args` / `proxy` JSON field. If the workstation needs an HTTP proxy, close its UE editor and clients, then merge the following into the project's ignored `Saved/Config/WindowsEditor/Engine.ini` and restart the clients. Replace the example address with an actual running HTTP proxy; preserve other INI sections.

```ini
[HTTP]
HttpProxyAddress=127.0.0.1:7897
HttpNoProxy=127.0.0.1,localhost,::1
```

This path applies to the current `UnrealEditor.exe -game` launcher. A direct UE command line can instead specify `-httpproxy=127.0.0.1:7897`. Keep the bypass list so local Backend HTTP requests remain direct. Verify the selected proxy in the Map client log and confirm real terrain appears; merely having a proxy process running is insufficient. Set `HttpProxyAddress=` to request direct access, or remove the key to restore the engine's OS-proxy fallback. Do not put a workstation proxy into shared project defaults. See the [Chinese map configuration instructions](../Docs/First-Run-Windows.md#4-设置地图服务) for the full sequence.

Map startup, UAV formation and Cesium request caching have shared defaults. DEMO starts in 3D over The Meadow using the shipped `Backend/mock_execution.json` origin; this explicit launch origin overrides the shared `[MapStartup]` presentation default. `startup_formation` also controls the Mock reset. Presentation does not relocate saved plans or custom Home files. Real-time startup uses UAV GPS first and Windows system location when no real UAV is connected, as described below. Cesium retains up to `131072` cache entries after pruning and checks pruning every `10000` requests. The policy is read by new UE processes, observes response cache headers and expiry, and is not an offline region package or a byte limit. Normal online use has `UseLocalTileServer=false` and needs no separate tile server. See [startup and cache details](../Docs/MarinaBayStartup.md).

## Starting and stopping

Choose a mode before starting. **Launch DEMO (Singapore)** uses local ports `19880/19881` and the existing `Saved/Stage1/data` Mock session. **Launch Realtime Mode** uses local ports `8080/8081` and `Backend/config.yaml` by default. The launcher starts or attaches to Backend first, validates its APIs and mode, then starts three independent instances of the same UE project. Real-time startup resolves the display origin through the priority rules below before opening any UE role. READY requires the expected instance for every role, a live owned process, a subscribed session and a fresh hydrated heartbeat. Shut down the current session before selecting another mode; the buttons cannot silently change a running session's mode.

### Real-time position initialization

Valid real-time Map startup opens the existing **2D basemap** at the resolved location; DEMO keeps its configured Singapore **3D** view. Native checking at the computer-derived location showed no ground in the initial 3D view while the 2D satellite imagery loaded normally. This initial 2D choice keeps real-time startup independent of local photorealistic 3D coverage. The toolbar still permits an explicit switch to **3D** where data is available. Raster configuration, authorization and provider credits remain unchanged; this does not establish worldwide 3D coverage.

The real-time Backend runs with the repository root as its working directory. Its selected configuration supplies the registry, UDP `port_map`, storage and existing execution policy. The shipped configuration uses `Backend/data/drones.json`; adjacent Backend state stays with that configured storage path. `Saved/Realtime` contains launcher ownership records, launcher logs, captured Backend stdout/stderr and UE absolute logs. Backend's own file log follows the selected configuration's `log.file` (default `logs/backend.log`). This branch does not create a Mock fixture, synthetic UAV registrations or a startup reset, and the launch button does not create or enable `real_execution.json` or start a flight task.

For UAV GPS startup, configure actual UAV connections and registry entries before launching; without a connected real UAV the computer-location path can be used. To use a workstation-specific Backend configuration, set `realtime_backend_config` in ignored `Launcher/config.local.json`; keep the two real-time endpoint fields consistent with that configuration's HTTP/WS ports. Both modes must use different Backend ports and launcher runtime directories. A running Mock Backend is rejected by real-time startup; an external Backend remains externally owned.

A valid UAV GPS fix can initialize immediately. Without one, real-time startup allows an eight-second real UAV discovery window (`realtime_device_wait`) before considering computer location. A qualifying UAV GPS record from `/api/drones` has `status=online`, `gps_fix=true`, `simulation=false` and `telemetry_source=received`, valid finite geographic coordinates other than `(0,0)` and a finite Backend `telemetry_received_at` no more than five seconds old by default. The receipt time is recorded when UDP telemetry arrives; polling does not refresh it. Among qualifying aircraft, the active UAV is preferred, otherwise the lowest numeric slot is used. GPS altitude is converted from AMSL to WGS84 ellipsoid height using `GeoidSeparationMeters` from `Config/DefaultGame.ini`, overridden by `Saved/Config/WindowsEditor/Game.ini`, matching the UE client.

A registry entry or outgoing connection probe alone does not count as a real connection; connection detection also requires Backend-received non-simulation telemetry. If any such real UAV is `online` or `connecting` but its GPS is invalid, the launcher continues waiting for UAV GPS up to `realtime_gps_timeout` (60 seconds by default); it does not replace that aircraft's location with the computer's. Only when there is no real UAV connection does it query **Windows system location**, allowing up to `realtime_computer_location_timeout` (15 seconds by default). If Windows does not supply altitude, the map uses an estimated `0 m` camera anchor and the status identifies the estimated elevation; this is not a UAV position, Home or flight altitude.

Disabled, denied, unavailable or timed-out Windows location produces a clear error. The launcher does not automatically change location permissions, guess a city from the IP address or fall back to Singapore. A failed position lookup closes only launcher-owned processes and opens no UE role. Rebuild an older Backend through `SetupDroneSecurity.cmd` if it lacks the `telemetry_receive_time` capability. Once initialized, new GPS or a change of location source does not automatically move the camera; restarting Map resolves the location again with the same priority. Synthetic tests of these rules do not establish native computer-location, GPS accuracy, physical-flight or map-alignment acceptance.

Command occupies the left half of the working area. Map and Video share the right half. These are normal resizable windows on one screen. Use **Focus** for detailed work and **Arrange Windows** to restore the overview. No monitor enumeration, display IDs, DPI mapping or borderless mode is required.

Use **Shutdown System** for normal session exit; closing the launcher uses the same shutdown flow and may require confirmation for active executions. In DEMO, an owned reachable Backend must acknowledge Mock pause before shutdown. In real-time mode shutdown does not call Mock pause and does not automatically pause real executions; handle active executions through the existing operational controls before stopping the session. **Stop / Restart** operates on an individual component and does not perform the whole-session pause step. Handle active executions before using component maintenance controls, especially DEMO Backend Restart, which applies the default Mock reset below. Existing compatible Backend processes may be reused; the launcher never terminates or restarts a Backend it did not launch. Logs and PID/role/start-time/executable records are in `Saved/Stage1` for DEMO and `Saved/Realtime` for real-time. A Windows job contains each owned process tree. Shutdown requests WM_CLOSE, waits eight seconds, then terminates only the retained process handle if necessary. Backend currently requires that bounded fallback; business mutations are persisted when acknowledged.

The launcher never clears persisted history. A fresh DEMO installation seeds four explicitly labelled Mock UAVs from `Backend/mock_execution.json`, without camera or flight connections. Existing aircraft and Home configuration files are preserved. Configuration deployment does not start execution.

The shipped configuration enables `mock_reset_on_start`. Whenever the launcher creates a new owned Backend for a Mock session, it waits for an acknowledged startup reset before opening clients. Eligible UAVs are arranged by numeric UAV identifier, eastward at 3 m intervals from the selected grass location within The Meadow at Gardens by the Bay: latitude 1.279445, longitude 103.862188, ellipsoid altitude 15 m. The location was chosen in the native map inside the lawn; the official The Meadow pin is approximately 55 m north, near a path, and was not used directly. The 15 m height is a near-ground display value for the currently loaded Google mesh, not automatic terrain snapping or a surveyed physical elevation. The formation is read from `startup_formation` in the source fixture `Backend/mock_execution.json`; it does not replace saved custom Home configuration. Attaching to an already running Backend or restarting only Command, Map or Video does not reset positions. Restarting the owned Backend creates a new session and performs the reset again.

Each reset saves a complete pre-reset document under `Saved/Stage1/data/mock-reset-history` and records a new position epoch. Completed history and route snapshots remain available. Eligible active Mock executions are marked ABORTED, scheduled Mock executions are CANCELLED, and their active reservations are released. Subsequent execution and return-home requests use the new session positions, including when a saved custom Home file still contains a previous location. Saved routes are not relocated; review their coordinates before starting an older plan in the new area. Received real telemetry, confirmed real execution positions and active real executions are protected; an active group containing a protected aircraft is skipped as a whole. Mock positioning does not mark hardware Online or issue flight commands.

The RHI startup test retains its failed result because Google tiles did not reach 99 percent loaded within the timeout; origin and spacing checks passed. DEMO uses local endpoints 19880/19881 and `Backend/build/Release/DroneBackend.exe` (existing `build-p53` installations are recognized as a fallback). DEMO unified shutdown warns about active executions and, while its owned Backend is alive and reachable, requires Mock pause acknowledgement before stopping owned processes. It does not automatically pause a reused external Backend. To preserve acknowledged Mock execution positions across owned Backend restarts, merge `"mock_reset_on_start": false` into `Launcher/config.local.json` and reopen the launcher before the next session. Starting Backend directly also does not invoke the launcher's reset. Executions paused by unified shutdown still require Resume. The normal DEMO configuration applies the startup reset described above; real-time mode always disables that reset.

3D fleet movement requires Backend capabilities `fleet_move_3d` and `map_fleet_controls`, advertised by `GET /`. Readiness checks both newly started and reused Backends before starting any client. An older executable can have valid plan/context snapshots while still rejecting Map fleet movement with `ROLE_FORBIDDEN`; it is now rejected with a rebuild instruction instead. Rebuild `Backend/build/Release/DroneBackend.exe` through `SetupDroneSecurity.cmd` after source updates, stop the old running Backend, and relaunch. `Scripts/FleetBackendCompatibility/verify.py` tests the resolved normal Launcher configuration with isolated Mock data and ports; it does not substitute a phase-specific backend build.

Checks: `python -B -m unittest discover -s Launcher -p "test_*.py" -v`. `record_acceptance.py` is a read-only native acceptance oracle; it does not drive UI or simulate client recovery.
