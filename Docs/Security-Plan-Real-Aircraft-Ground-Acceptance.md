# 安保方案真机地面验收清单

适用于一架已登记真机和一架模拟机。用 Command 和 MAP 在同一个 Real Backend 上走完关联、单机预演、复核、真机检查和部署。**本轮终点是打开「任务执行确认」页，核对内容并截图，然后点「取消」。保持真机未解锁和定时启动关闭，「确认开始任务」按钮留在未按下状态。** 本轮结论填写「地面验收通过，飞行未验收」或「地面验收未通过」。 [预演与真机方案设计](Security-Plan-Rehearsal-Real-Execution-Design.md)

## 接入前检查

- [ ] 使用包含模拟机关联和真机草稿功能的 Backend、Command 和 MAP。使用现场验收专用的数据目录和唯一方案名。记录 Git 提交、实际运行的 Backend 和 UE 版本，以及现场时间和时区。
- [ ] 真机保持断开时先取 Backend 基线快照，确认验收环境没有预约、活动执行、待恢复的暂停执行或设备控制占用。复查相关 Pilot 或外部控制会话处于未占用状态。已有预约可在到期时进入执行，发现遗留任务先中止本轮，由会话所有者处理后重取基线。 [重启后的执行状态](P54-Real-Adapter.md#restart-shutdown-and-control-ownership)
- [ ] 确认现场配置的 Real 任务适配器使用本机已验证的坐标标定，并匹配当前登记 ID。实时启动入口负责启动和连接组件，Real 任务适配器由现场 Backend 的数据目录配置决定。通过 `GET /api/security-plans` 核对 `execution_adapter = Real`。在同一个 Real Backend 上，分配给模拟机的预演仍走软件预演。 [实时启动说明](../Launcher/README.md#starting-and-stopping) · [Real 适配器和标定要求](P54-Real-Adapter.md#default-and-activation-boundary)
- [ ] 通电前按机型的地面测试规程准备设备。全程在地面站确认飞控保持未解锁，保留现有安全闭锁。保持 Offboard、Pilot 接管、遥控动作和电机测试停用。真机状态异常或出现意外动力输出时，由现场人员按设备既定应急规程处理，并结束本轮验收。 [PX4 飞控状态说明](https://docs.px4.io/main/en/getting_started/px4_basic_concepts)
- [ ] 接入已登记的测试真机，核对机身标识、Backend 登记 ID 和 Command 显示的 `UAV-xx` 编号。检查实际配置的遥测链路收到该机的实时数据。Command 和 MAP 连接同一个 Backend，状态均为在线。

## 原生界面验收

| 步骤 | 在哪里操作 | 通过条件和留证 |
| --- | --- | --- |
| 1. 关联设备 | 在 Command 机队页新增一架模拟机，在「关联真机」中选择已核对登记身份的真机并保存。 | 模拟机行显示已关联的 `UAV-xx`。记录模拟机编号、关联真机编号和后台登记 ID。 |
| 2. 配置模拟任务 | 在 Command 新建方案和一个任务，仅分配刚创建的模拟机并保存。在 MAP 保存该任务的验收航线，结束路线编辑。 | Command 同时显示模拟机和候选真机。记录任务 ID、保存的航线版本，并确认 MAP 的航线编辑占用已释放。 |
| 3. 运行并复核预演 | 在原模拟任务点击「运行预演」。在 MAP 看进度和回放，在 Command 核对全部航点完成后点击「复核通过」。 | 预演记录属于该模拟机，Backend 显示 `simulation=true`、`rehearsal=true`、`state=COMPLETED`，并保存 `rehearsal_review`。该真机保持未解锁、无运动控制指令。 |
| 4. 建立真机草稿 | 点击「准备真机执行」，核对已预填的 `UAV-xx` 和航线版本，然后点「确认分配真机」。 | Command 打开独立的「真机方案 · 待检查」。真机草稿关联步骤 3 的预演记录，实际分配的登记 ID 与步骤 1 一致。用「查看源预演」核对来源，然后回到真机草稿。 |
| 5. 做真机检查 | 在真机草稿的任务行点击「检查并部署」，进入「部署前检查」。核对在线状态、有效 GPS、本地定位、标定锚点和控制占用。 | Backend 校验通过，当前内容版本显示可部署。遇到阻塞项时停在检查页，记录实际原因和快照。 |
| 6. 部署方案 | 在部署前检查页点击「部署方案」。等 Backend 完成重新检查、方案复核并保存部署。 | Command 显示「真机方案 · 已部署 · 待开始」，Backend 的方案状态为 `DEPLOYED`，有 `deployment_id` 和对应快照。记录部署 ID、内容版本与部署时间。真机仍未解锁，执行集合没有新增真机记录。 |
| 7. 打开开始确认页 | 在已部署真机方案中点击「开始真机执行」。这里打开「任务执行确认」页。核对方案名、真机编号、航线版本和航点数，保持「定时启动」关闭。 | **到这里停手并截图。** 保留「确认开始任务」未按下。此时 Backend 仍为 `DEPLOYED`，启动和预约记录均未新增。 |
| 8. 取消并收尾 | 截图后点「取消」退出执行确认。回读状态和地面站遥测，按现场流程结束本轮地面验收。 | 确认页关闭，方案仍「已部署 · 待开始」，部署 ID 与步骤 6 相同。真机仍未解锁，控制记录没有出现任务启动、解锁或移动指令。 |

配置检查和部署都使用当前内容版本。修改航线、预演设备或编队参数后，重新预演、复核并从对应的预演记录生成或打开真机草稿。遇到界面超时先回读当前草稿或部署，再决定是否重试。 [方案配置与占用](PLAN-Configuration-Workflow.md) · [部署校验和快照保存](../Backend/storage/security_plan_store.h)

## 常见阻塞

| 看到的现象 | 停在哪里 | 核对项 |
| --- | --- | --- |
| 「真机执行尚未配置」或 `REAL_EXECUTION_DISABLED` | 真机检查 | 核对实际连接的 Backend 与存储目录，并确认 `execution_adapter = Real`。 |
| 真机离线、GPS 无效、定位数据过期或锚点变更 | 真机检查 | 核对真机在线、近期收到真实遥测、本地定位有效。锚点不符由现场人员按已有标定流程处理。保持未解锁并复检。 |
| 「设备已变更」或 `REAL_UAV_REGISTRATION_CHANGED` | 关联、分配或真机检查 | 同一槽位换机后登记身份可能不同。核对现役设备，重新选择并生成针对该身份的真机草稿。 |
| MAP 离线、编辑或配置会话仍占用，或设备已被任务、Pilot 占用 | 当前操作 | 核对 Command 和 MAP 在线。由原会话所有者结束对应的编辑或配置，并处理已有任务或控制占用后复检。 |
| 已部署但入口缺失，或确认页显示定位、设备等阻塞 | 已部署状态或确认页 | 记录显示内容和 Backend 快照，核对实际适配器、当前任务、设备和航线。由现场人员排除阻塞后，从部署记录重新核对。 |

## 记录和判定

原生界面截图、本轮 Backend 快照和现场设备证据按时间对齐保存。真实坐标、设备序列号、内部地址和原始日志留在现场验收资料中，提交到仓库的记录可用脱敏编号。

| 证据 | 记录内容 |
| --- | --- |
| Command 和 MAP 原生界面 | 设备关联与任务分配、MAP 预演完成、Command 复核和真机草稿、部署成功、开始确认页、取消后状态。 |
| Backend 只读回读 | 用现场 Backend 的 `GET /api/security-plans` 保存基线、部署后和取消后三份快照。对比源预演 ID、真机登记 ID、`deployment_id` 与 `executions`。允许新增本轮软件预演记录。确认新增 `simulation=false` 的执行记录和新增 `SCHEDULED` 记录均为零。 |
| 真机和接入日志 | 用 `GET /api/drones` 和地面站回读验收设备的状态，核对 `simulation=false`、`telemetry_source=received`、`armed=false` 及记录时间。用现场已有的控制日志或发送侧记录核对该机在验收时间窗内的任务启动、解锁和移动指令数均为零。 |

- [ ] 八个步骤的通过条件均满足，开始确认页和取消后的状态均有截图。
- [ ] 方案仍为已部署且待开始，零新增真机执行和预约，现场遥测持续未解锁，相关控制指令数核验为零。
- [ ] 记录验收人、现场时间、版本、模拟机编号、真机登记 ID、源方案和任务 ID、源预演 ID、真机方案 ID、航线版本、部署 ID 与证据位置。缺少证据时标记相应项目「未核验」并写明所停步骤。

通过后可在现场记录写下「真机接入、模拟预演、真机检查和部署通过。已打开并取消任务执行确认。本轮未进行飞行验收」。
