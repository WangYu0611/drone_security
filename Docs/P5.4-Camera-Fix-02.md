## Scope and implementation

The Map camera now receives native screen-coordinate pointer events for all three buttons. A single gesture state records button, origin, last consumed position and threshold crossing. Release consumes only the remaining displacement; cancellation drops the gesture when input leaves the map or capture is lost. Inspector and popup hit paths block camera input. No gameplay MouseY polling is mixed with absolute screen Y. Idle pointer movement does not run camera hit testing. When an editable waypoint body is hit, the pointer preprocessor owns that complete body gesture and delegates movement/release to the existing PlayerController editing transaction, preventing delayed gameplay bindings from processing it again.

Pan changes only the focus target. Actual focus, distance and rotation exponentially converge; no drag-derived velocity pushes the target after release. Pan uses the camera yaw and a ground-relative pitch basis. Clicks and sub-threshold movements do not pan. Position tails below 0.01 Unreal units (0.1 mm) terminate exactly; parameters retain the existing CommandMapCamera configuration source.

2D wheel zoom holds the cursor's ground-plane anchor throughout interpolation, using one consistent camera geometry. Repeated wheel input changes bounded target distance; excess wheel input at a limit does not move the anchor. 3D dolly retains the observation pivot. Focus and mode changes preserve damping and cancel obsolete gestures/zoom anchors.

The only shared PlayerController changes are Map-specific input handling: double-click waypoint focus, precedence of the waypoint body over coincident gizmo axes, and avoiding polled mouse updates during an owned native body gesture. Native QA found that dragging the body at the common X/Y gizmo origin could choose the first axis; subsequent native testing also exposed deferred press handling that could read the release position and append a point. The new body hit starts the existing planar movement/deferred update/undo path, with a screen-space radius derived from the same configured drag threshold. Inspector fields, route schemas, Backend, Command Situation Map and Video implementations are unchanged.

### Native-discovered wheel event defect

Build-04 native screenshots `final-pan-down-02`, `final-zoom-in-01` and `final-zoom-roundtrip-settled` expose a small round-trip offset after moving the pointer from the drag endpoint to a different zoom position. The wheel preprocessor polled PlayerController mouse position while handling the Slate event, allowing the preceding position to be used for the first anchor. The production wheel handler now uses `FPointerEvent::GetScreenSpacePosition()` and the owning viewport's cached geometry directly. The test supplies an explicit screen event position independently of the OS cursor and verifies the expected ray slope and settled round trip with the same 0.01-unit tolerance. This is a new, reproduced finding; it is not presented as the cause of the historical Press/Release or Drag Down assertions.

The first run of that new test (`ue-1790425336986259100`) retained a settling assertion failure. Its fixed two-second wait was insufficient for zoom's 0.20s time constant: a 2250-unit distance change retains approximately 0.102 units after two seconds, exceeding the existing 0.01-unit stop threshold. That specific zoom check now advances four seconds and logs event position, expected focus, target, actual and delta. The tolerance and production damping parameters are unchanged; existing two-second pan convergence assertions remain intact.
