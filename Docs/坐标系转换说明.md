# 坐标系转换说明（当前实现）

> 更新时间：2026-09-09。公式以 `Backend/conversion/coordinate_converter.cpp`、`Source/UE5DroneControl/DroneOps/Network/DroneNetworkManager.cpp` 和当前遥测解析代码为准。

## 1. 坐标系定义

| 坐标系 | 轴 | 单位 | 当前用途 |
|---|---|---|---|
| UE 相对偏移 | `X` 前、`Y` 右、`Z` 上 | cm | UE 发给后端的单机/路径目标、后端推给 UE 的镜像位置 |
| PX4/Jetson NED | `N` 北、`E` 东、`D` 下 | m | 后端内部控制目标、遥测位置和 PX4 `TrajectorySetpoint` |
| WGS84 | latitude/longitude/height | 度、m | GPS 遥测、Cesium 地理目标和上电锚点 |
| Cesium/UE 世界坐标 | 场景世界坐标 | UE 单位通常为 cm | 地图点击、路径 Actor、Cesium 地理转换后的场景位置 |

后端 JSON 控制的 `target` 明确声明：`frame=NED`、`reference=power_on_origin`、`unit=m`。Jetson 不再对目标做额外轴交换或单位换算。

## 2. 后端线性转换

源码 `CoordinateConverter` 当前公式：

```text
NED → UE 相对偏移
UE_X = N × 100
UE_Y = E × 100
UE_Z = -D × 100

UE 相对偏移 → NED
N = UE_X × 0.01
E = UE_Y × 0.01
D = -UE_Z × 0.01
```

例：UE 目标 `(1000, 2000, 500) cm` 转为后端目标 `(10, 20, -5) m`；NED `(10,20,-5)m` 回到 UE 为 `(1000,2000,500)cm`。

这组函数只负责单位/轴向线性转换，不负责把 Cesium 绝对世界坐标减去某架无人机的锚点。

## 3. 实时遥测链路

1. Jetson 上报 `position` 或有效的 `local_position`，坐标是本机上电原点下的 `[N,E,D] m`。
2. 后端 `UdpReceiver` 仅在 `local_position_valid=true` 且数据有限有效时用 `local_position` 覆盖内部 `position_ned`。
3. 后端 `NedToUeOffset` 转成 UE 相对偏移 cm。
4. 后端通过 WebSocket `telemetry` 推送 `x/y/z`、姿态、速度、电量、GPS、armed/offboard 和锚点有效性。
5. UE 的 `UDroneNetworkManager` 解析消息，写入 `UDroneRegistrySubsystem`，镜像 Actor 再从 Registry 更新位置/姿态。

遥测中的 `gps_lat/gps_lon/gps_alt` 是当前全球位置；它不能替代本地 NED 位置，也不能作为控制目标的原点字段。

## 4. GPS 锚点与 Cesium

### 4.1 上电锚点

- 后端收到首个有效 GPS 遥测时，为该无人机保存 `GpsAnchor`。
- `power_on`/`reconnect` 事件可携带 `gps_lat/gps_lon/gps_alt`。
- `GET /api/drones/{id}/anchor` 没有有效锚点时返回 HTTP 425。
- 失联后重新上电可能产生新的本地 NED 原点；后端清理旧坐标目标，UE 必须重新缓存锚点。

### 4.2 UE/Cesium 高程

UE 的地理目标面板使用 `GeoidSeparationMeters` 将海拔/正高转换成 Cesium 使用的椭球高：

```text
ellipsoid_height = altitude_msl + GeoidSeparationMeters
```

当前 `Config/DefaultGame.ini` 的默认值是 `0.0`，只有在上游高度本身已是椭球高时才成立；真实区域应由测绘/飞控数据确认后配置。

### 4.3 地理目标派发

- UE 地理目标面板先将 WGS84 经纬高转换到当前 Cesium Georeference 下的 UE 世界坐标。
- 派发给单机 move 或阵列后端前，必须得到“目标机上电原点下的 UE 相对偏移”。
- 当前后端 `UeOffsetToNed` 不接受 Cesium 绝对世界坐标；直接传入会把世界坐标误解为相对偏移。

## 5. 多机阵列的原点风险

每架机的 `power_on_origin` 独立，因此同一个公共地理目标不能直接复用参考机的 NED/UE 偏移。正确流程应是：

```text
公共 WGS84 目标
  ├─ 结合 Drone A 的 GPS 锚点 → A 的本地 NED → A 的 UE 相对偏移
  ├─ 结合 Drone B 的 GPS 锚点 → B 的本地 NED → B 的 UE 相对偏移
  └─ ...
```

当前 `SequenceDispatchPanelWidget` 的部分路径重映射仍有“把参考锚点加回路径后直接派发”的风险。外场前必须确认每条路径的坐标在进入 `POST /api/arrays` 时已经是对应执行机的相对偏移，而不是 Cesium/UE 世界坐标。

## 6. 控制链路转换

UE → 后端：

```text
UE 相对偏移 cm
  → WebSocket mode 目标或 REST 阵列 waypoint
  → 后端 UeOffsetToNed
  → NED m
  → UDP JSON target
```

后端 → Jetson 的 JSON 目标示例：

```json
{
  "target": {
    "frame": "NED",
    "reference": "power_on_origin",
    "unit": "m",
    "north": 10.0,
    "east": 20.0,
    "down": -5.0
  }
}
```

Jetson → 后端：

```text
PX4 local_position [N,E,D] m
  → Jetson YAML
  → 后端 position_ned
  → NedToUeOffset
  → WebSocket telemetry x/y/z cm
```

## 7. 验证样例

无真实飞控时可以通过 debug 接口注入：

```powershell
curl.exe -X POST http://127.0.0.1:8080/api/debug/drone/1/inject `
  -H "Content-Type: application/json" `
  -d '{"position":[1,2,-3],"q":[1,0,0,0],"velocity":[0,0,0],"battery":85,"gps_lat":39.9,"gps_lon":116.3,"gps_alt":50,"gps_fix":true,"local_position":[1,2,-3],"local_position_valid":true}'
```

预期 WebSocket `telemetry` 中的 UE 相对偏移是 `(100, 200, 300) cm`。这只验证后端解析和线性转换，不证明 Cesium 地理对齐或 PX4 实机运动正确。

## 8. 必须避免的误用

- 不要把 UE cm 当 NED m 直接发给 Jetson。
- 不要把 `VehicleOdometry` 或无效 `local_position` 当作 PX4 `TrajectorySetpoint` 同一坐标证据。
- 不要用当前遥测位置覆盖后端期望目标。
- 不要把全局 Cesium 世界坐标直接送进 `UeOffsetToNed`。
- 不要因为 `command_ack` 或 UDP send 成功就宣称坐标目标已由 PX4 执行。
