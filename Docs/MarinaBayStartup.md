# Marina Bay / The Meadow startup map

The current Map startup is centered on a grass location inside The Meadow at Gardens by the Bay. The Command overview keeps its independent 2D map and follows the accepted Mock aircraft positions in Singapore.

- WGS84 origin: latitude `1.279445`, longitude `103.862188`, ellipsoid height `15 m`.
- Initial camera: `2400 m` distance, pitch `-50` degrees, yaw `-35` degrees. Locate provides the close fleet view.
- Mock UAVs: numeric identifier order, eastward at `3 m` spacing. Each new Launcher-owned Mock Backend session resets eligible aircraft; attaching to an existing Backend or restarting only a client preserves positions.
- **Locate** still brings the selected aircraft or the whole fleet into a close view for selection. The city overview does not promise separate screen footprints for aircraft only 3 m apart.

Presentation defaults live in `[MapStartup]` and `[CommandMap]` in `Config/DefaultGame.ini`; the corresponding simulation origin and default homes are in `Backend/mock_execution.json`. Explicit main-menu coordinates take precedence over the presentation default. Existing plans, routes, deployment snapshots and custom Home files are not relocated when the startup default changes. Height is relative to the WGS84 ellipsoid, not above terrain or a building.

The grass center was chosen in the native map. The official The Meadow pin is approximately 55 m north, near a path, so it was not used directly. The `15 m` ellipsoid height is a near-ground display value for the currently loaded Google mesh. It does not perform automatic terrain snapping and is not a surveyed physical elevation or a guaranteed clearance. Existing historical plans and routes are not moved to the grass location.

## Online 3D source

The project uses its existing Cesium ion **Google Photorealistic 3D Tiles**, asset `2275207`. In 3D this source takes priority over duplicate OSM buildings and terrain. In 2D the existing raster surface remains available. The Google tileset requests a maximum screen-space error of `4` pixels instead of the plugin default `16`; this improves requested detail but cannot add geometry absent from the provider. Actual resolution and loading speed still depend on coverage, network and available GPU memory.

The existing local Cesium connection supplies authorization. No token is stored in these defaults. Google/provider credits remain generated by Cesium and must remain visible above the application HUD. The normal online stream is used; this change does not create an offline Google dataset.

## Disk request cache

As of 2026-10-23, the Cesium HTTP disk cache retains up to `131072` request entries after pruning, increased eightfold from `16384`. `RequestsPerCachePrune=10000` keeps the existing cleanup frequency. In the installed Cesium 2.28 plugin, the former `MaxCacheBytes` setting is unsupported and has been removed; entry capacity is not a byte limit, and actual disk usage depends on tile sizes. This workstation currently uses `cesium-request-cache.sqlite` in the project root. Keep that database and its WAL/SHM files out of source control.

Only responses permitted by their HTTP headers are cached. Expired or `no-cache` responses still require revalidation, and `no-store` responses are not retained. These settings do not pin an area permanently, bypass provider expiry, download an offline package, or resolve network connection timeouts. See [Google's cache requirements](https://developers.google.com/maps/documentation/tile/policies).

The plugin reads cache settings into process-local static objects, so already-running clients keep their previous policy until restarted. The configuration change needs no compilation. A fresh read-only commandlet reflected `MaxCacheItems=131072` and `RequestsPerCachePrune=10000`; its Python assertions passed, while the overall Editor process retained exit 1 from existing plugin initialization errors. No map, cache database or Backend was accessed by the verification script. Existing Mock executions were left running; the Backend was not restarted. GPU tile-cache memory, texture budgets and visual detail are unchanged. See [capacity verification](../Evidence/CesiumCacheCapacity/20261023/acceptance.json).

The texture streaming pool is bounded at `3072 MB`. The VRAM limit is enabled for the Launcher `-game` client; Unreal excludes Editor/PIE from that limit. A fully streamed desktop view exceeded the `1536 MB` and `2048 MB` trial pools on the 6 GB validation GPU. Unreferenced ray-tracing LODs are allowed to be evicted (`r.RayTracing.NumAlwaysResidentLODs=0`) instead of being pinned by default. Texture streaming, ray tracing, and diagnostic warnings remain enabled. The 2026-10-22 large-window native check at the former waterfront location still showed a small texture-budget warning near language changes; this is not a guarantee of warning-free operation on all views or machines. Lower-memory machines may need a smaller detail budget.

## Free allowance and coverage

Checked on **2026-10-22**: the Cesium ion Community plan lists **1,000 Google 3D root tiles per month**, with eligibility for personal noncommercial use, evaluation and qualifying education. Commercial and government deployment must be checked against the account's applicable plan and terms. An existing token does not establish the account's remaining allowance. This implementation does not activate a paid plan or enable Google Cloud billing. See [Cesium ion pricing and licensing](https://cesium.com/platform/cesium-ion/pricing/).

Google Maps API-key access is a separate billing route; its allowances must not be confused with Cesium ion allowances. See [Google Map Tiles usage and billing](https://developers.google.com/maps/documentation/tile/usage-and-billing) and [attribution policies](https://developers.google.com/maps/documentation/tile/policies).

[Google's coverage table](https://developers.google.com/maps/coverage) lists Singapore as supported for 3D tiles. That is country-level coverage, not a guarantee for every Marina Bay building. Runtime validation must show actual streamed geometry and the visible waterfront/landmarks; merely creating a tileset actor is insufficient.
