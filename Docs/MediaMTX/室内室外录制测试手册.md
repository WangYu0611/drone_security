# 室内/室外视频与元数据测试手册（当前基线）

> 更新时间：2026-09-09
> 本手册将“本地 MediaMTX 演示”和“真实 Jetson 摄像头/SfM”分开。室内测试不能证明飞行安全、GPS 有效或 PX4 执行。

## 1. 安全要求

室内：

- [ ] 拆桨或完全断开电机动力，并固定机体。
- [ ] 不解锁、不起飞；只做摄像头、视频、元数据和 UI 测试。
- [ ] 室内 GPS 无效是允许结果，不得为了获取 GPS 解锁。

室外：

- [ ] 使用符合当地法规和场地要求的空旷区域。
- [ ] 由有资质/有能力的人员负责飞行安全、急停和人工接管。
- [ ] 先启动录制和数据链路，静止/落地后再停止并保存日志。

## 2. A 类：本地循环视频演示

准备：

- `D:\RedAlert\UE5DroneControl\tools\MediaMTX\mediamtx.exe`
- `tools/MediaMTX/mediamtx.yml`
- 脚本默认的 FFmpeg/FFprobe 路径和 `D:\DroneData\recordings\drone-4` 下的三段 MP4

启动：

```powershell
cd D:\RedAlert\UE5DroneControl
.\tools\MediaMTX\start_demo_streams.cmd
```

检查：

```powershell
Test-NetConnection 127.0.0.1 -Port 8554
Test-NetConnection 127.0.0.1 -Port 8889
ffprobe.exe -v error -rtsp_transport tcp -select_streams v:0 `
  -show_entries stream=codec_name -of csv=p=0 `
  rtsp://127.0.0.1:8554/drone-1
```

- [ ] 后端 `GET /` 可达（脚本会尝试启动后端）。
- [ ] FFprobe 读取 `drone-1/2/3`。
- [ ] 浏览器打开 `http://127.0.0.1:8889/drone-1` 连续播放。
- [ ] UE 中键打开对应无人机视频窗口，画面一致。
- [ ] 关闭、重开窗口可重复加载；关闭只影响浏览器页，不停止 MediaMTX。
- [ ] 记录脚本输出和 `tools/MediaMTX/*ffmpeg*.log`，但不要把日志本身当作当前健康证明。

当前 `tools/MediaMTX/mediamtx.yml` 的 `pathDefaults.record=false`，该演示默认不把循环输入再次录制。需要录制时必须显式修改配置并确认目录/磁盘。

## 3. B 类：真实 Jetson 摄像头/SfM（外部依赖）

仓库不包含完整 Jetson 采集脚本和 ROS2 工作区，以下内容必须按外部 Jetson 项目的实际版本填写后再执行：

| 项目 | 实际值 |
|---|---|
| Jetson IP | |
| MediaMTX 主机 IP | |
| 后端 IP/端口 | |
| DroneId/slot | |
| 相机话题和分辨率 | |
| GPS/局部位姿话题 | |
| Jetson publisher 版本/commit | |
| 录像和元数据目录 | |

启动顺序：

1. 后端：

   ```powershell
   cd D:\RedAlert\UE5DroneControl
   .\Backend\build\Release\DroneBackend.exe .\Backend\config.yaml
   curl.exe http://127.0.0.1:8080/
   ```

2. MediaMTX：

   ```powershell
   cd D:\RedAlert\UE5DroneControl\tools\MediaMTX
   .\mediamtx.exe .\mediamtx.yml
   ```

3. Jetson：根据外部项目文档启动摄像头、ROS2/PX4、RTSP publisher 和逐帧元数据上传程序。
4. 浏览器先打开 `http://<mediamtx-host>:8889/drone-N`，再进入 UE 验证 WebBrowser。

## 4. 真实视频检查

- [ ] 摄像头帧率、分辨率、编码和时间戳有日志证据。
- [ ] MediaMTX RTSP/WebRTC 可读，跨机时 ICE 地址可达。
- [ ] UE 视频窗口打开/关闭/重开正常。
- [ ] `GET /api/drones` 的 `video_url` 与当前 MediaMTX 路径一致。
- [ ] Jetson 上报的逐帧 metadata 通过 `POST /api/video-metadata/batch`，后端返回成功且批次幂等。
- [ ] 检查后端 `storage.video_metadata_path` 下的 `session.json`、批次和完成标记（由当前元数据 store 实现决定）。
- [ ] 室内 GPS 无效帧不伪造 `0,0`；可用的局部位置/姿态字段按 schema 保存。
- [ ] 视频文件、元数据、后端日志、Jetson 日志使用同一 mission/session 标识关联。

## 5. 结论模板

```text
本地 RTSP：通过/不通过；证据：
浏览器 WebRTC：通过/不通过；证据：
UE 视频窗口：通过/不通过/未测；证据：
跨机网络：通过/不通过/未测；证据：
metadata batch：通过/不通过/未测；证据：
真实摄像头/SfM：通过/不通过/未测；版本：
未验证：控制、GPS 地理对齐、PX4 飞行执行
```

不要因为视频连续播放就宣称无人机在线、控制可靠或 PX4 已执行。
