# 系统架构设计（当前实现）

> 更新时间：2026-09-09。本文只描述当前仓库代码的职责和已实现链路；需求草案、历史 Python bridge 和旧二进制协议不作为现状依据。详细字段见 [PROJECT_FACTS.md](PROJECT_FACTS.md) 与 [接口与通讯数据规范.md](接口与通讯数据规范.md)。

## 1. 总体架构

```text
┌──────────────────────── UE5 / Windows ────────────────────────┐
│ CesiumWorld / MainMenu                                         │
│ UDroneNetworkManager (GameInstanceSubsystem)                  │
│  ├─ UDroneHttpClient       REST: registry / arrays / metadata   │
│  ├─ UDroneWebSocketClient  WS: control + telemetry/events       │
│  ├─ UDroneRegistrySubsystem  authoritative UE-side mirror       │
│  ├─ DroneOpsPlayerController  input, selection, path/video UI    │
│  └─ GameMode / Receiver / Shadow Actor / Path Actor              │
└────────────────────────────┬──────────────────────────────────┘
                             │ TCP 8080/8081
                             ▼
┌────────────────────── DroneBackend / C++17 ────────────────────┐
│ HttpServer + WsManager                                          │
│  ├─ DroneManager: registry context, state, anchor, queues        │
│  ├─ HeartbeatManager: JSON control resend and hold               │
│  ├─ AssemblyController + AssemblyPlanner: gather/assign/safety   │
│  ├─ ExecutionEngine: scout/patrol/attack + avoidance             │
│  ├─ CoordinateConverter / GpsAnchorManager                       │
│  ├─ UdpSender: JSON v1 control                                   │

└───────────────┬───────────────────────────┬───────────────────┘
                │ UDP JSON v1                │ UDP YAML
                ▼                           ▲
        Jetson bridge / PX4              Jetson bridge
                │                           │
                └──────── ROS2 / PX4 ───────┘

UE WebBrowser ───────────────► MediaMTX WebRTC（独立于控制链路）
```

## 2. 职责边界

### 2.1 UE5

- 负责用户交互、Cesium/UE 世界坐标、路径和阵列编辑、影子机预演、无人机列表与视频窗口。
- `UDroneNetworkManager` 负责 HTTP/WS 生命周期、3 秒注册表轮询、协议消息路由和严格本地预演隔离。
- `UDroneRegistrySubsystem` 保存 UE 侧无人机身份、在线状态、遥测快照、多选状态、任务状态和 GPS 锚点缓存。
- `DroneOpsPlayerController` 汇聚地图点击、暂停/恢复、任务派发、地理目标、路径播放和视频窗口入口。
- `ARealTimeDroneReceiver` 等镜像 Actor 只负责将后端遥测表现到 UE 场景，不拥有后端事实。

### 2.2 后端

- `HttpServer` 是 REST/WS 边界；正式接口和 debug 接口均在 `Backend/http/http_server.cpp` 注册。
- `DroneManager` 维护每架机的状态机、最新遥测、GPS 锚点、命令队列、控制目标和 UDP 上下文。
- `HeartbeatManager` 以配置的 5Hz 发送控制报文；move 默认重复 5 次，随后持续发送 hold，直到新目标或暂停替换它。
- `AssemblyController` 负责集结状态、到位统计、超时和安全圆柱规划；`AssemblyPlanner` 用最优匹配和高度分离处理集结冲突。
- `ExecutionEngine` 在集结完成后执行 `scout`/`patrol`/`attack` 航点，并由独立循环做预测避障和目标恢复。
- `VideoMetadataStore` 将 Jetson 上传的元数据批次按 mission/drone/sequence 幂等写入 JSONL。

### 2.3 Jetson/PX4

- Jetson 接收后端 JSON 控制并执行 3-of-5 应用确认；后端不直接接触 PX4 ROS2 话题。
- Jetson 持续发送 YAML 遥测；PX4 Offboard 的 50Hz setpoint 由 Jetson 负责，不等于后端 `heartbeat_hz`。
- 本仓库未包含可作为真实机载验收依据的 Jetson 脚本；部署时必须成套匹配协议版本。

## 3. 状态与数据所有权

| 数据 | 权威所有者 | UE 用途 |
|---|---|---|
| 注册记录、slot、持久化 ID | 后端 `drones.json`/`DroneManager` | 列表和身份镜像 |
| 连接状态 | 后端状态机 | UI 状态展示 |
| 实时遥测 | Jetson/PX4 → 后端 | UE 镜像、告警、到达判断 |
| 期望目标/hold 目标 | 后端队列和任务执行器 | 不得被实测位置覆盖 |
| GPS 上电锚点 | 后端 `GpsAnchorManager`，UE 缓存副本 | 地理定位和坐标重建 |
| 阵列任务状态 | 后端 `task_states_` | `drone_task_state`/`GET /api/drones` |
| UE-only 敌对目标、确认和本地预演 | UE | 不通过后端任务状态伪造 |

关键不变量：

1. `command_ack` 只表示后端接受，`control_ack` 才表示 Jetson 通过应用层阈值并写入 setpoint 缓存。
2. 遥测实际位置不能覆盖期望目标；pause 才用最新实测位置创建 hold。
3. 重新上电或重连可能改变本地 NED 原点，后端清理旧坐标目标，UE 必须刷新锚点。
4. 单机目标使用目标机自己的上电原点；多机阵列必须逐机做原点补偿。

## 4. 任务状态机

```text
Idle
  └─ POST /api/arrays
       ▼
  Assembling ──全部到位──► Ready/assembly_complete ──► ExecutionEngine
       │                                      │
       └─超时──► Timeout/error               ├─ scout: 逐点/可闭环
                                             ├─ patrol: 逐点/目标事件切换
                                             └─ attack: 到点后完成

任何执行状态 ── pause ──► Paused ── resume ──► 原任务状态
执行目标 ──预测冲突──► Avoiding ──恢复窗口到期──► 原目标
```

阵列任务状态通过 `drone_task_state` 推送，UE 不应只根据“点击了哪个模式”自行推断后端完成情况。

## 5. 控制可靠性

每个 move 形成一个包含 `session_id`、`command_id`、`sequence`、slot 和 NED 目标的逻辑指令。后端按 5Hz 重发 5 个 `repeat_index`，Jetson 在时间窗内收到 3 个不同重复索引且负载一致的包后应用；迟到旧 sequence、旧 session、slot 串包或同命令负载冲突必须拒绝。

这只提供“允许有限丢包时的最新目标可靠应用”，不提供网络中断时的必达。后端 UDP `send_to` 成功也不等价于 Jetson 收到。

有限速度从 UE `speed`/航点 `segmentSpeed` 传入，后端保持在 `[0.5,15] m/s`；0 表示兼容旧调用的 unlimited marker，序列化为 JSON 字符串 `"NaN"`。

## 6. 当前架构风险

- 阵列重映射仍可能把 Cesium/UE 世界坐标当成后端相对偏移；多机 GPS/NED 原点补偿必须专项完成后才能外场验收。
- `server.debug=true` 默认开启，真实部署应评估是否关闭 debug 路由。
- UE 5.7、后端和 Jetson 必须同步协议版本；旧 24 字节控制包不能与 JSON v1 混用。
- MediaMTX 视频是独立链路，视频可播放不证明控制链路可用。
- 代码结构和静态测试不能替代 UE Play Mode、跨机网络和真实飞控验收。
