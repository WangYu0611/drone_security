# 接口与通讯数据规范（当前实现）

> 更新时间：2026-09-09。实现依据：`Backend/http/http_server.cpp`、`Backend/config.yaml`、`Backend/communication/udp_sender.cpp`、`Backend/communication/udp_receiver.cpp`、`Source/UE5DroneControl/DroneOps/Network/`。
> 相关文档：[PROJECT_FACTS.md](PROJECT_FACTS.md)、[架构设计.md](架构设计.md)、[坐标系转换说明.md](坐标系转换说明.md)。

## 1. 通讯总览

```
UE5 ── HTTP REST :8080 ──► DroneBackend
UE5 ◄─ WebSocket :8081/ws ► DroneBackend
                              ├─ UDP JSON v1 ──► Jetson/PX4 控制
                              └─ UDP YAML ◄───── Jetson/PX4 遥测

UE5 ── browser WebRTC video_url ──► MediaMTX（独立，不属于控制协议）
```

控制链路与遥测链路分离。HTTP/WS 成功、UDP `send_to` 成功、后端 `command_ack` 都只代表相应层完成，只有 YAML 中的 `control_ack` 才代表 Jetson 达到应用确认阈值并写入 PX4 setpoint 缓存。

## 2. 通用约定

- 默认 HTTP：`http://<backend-host>:8080`；默认 WS：`ws://<backend-host>:8081/ws`。
- ID 同时支持数字 `1` 和字符串 `"d1"`；后端注册返回两种形式。
- UE `x/y/z` 是目标机本次上电原点下的相对偏移，单位 cm；UDP JSON `target` 是 NED 米。
- 正式错误主体当前为 `{"detail":"..."}`；WS 错误为 `{"type":"error","code":...,"message":"..."}`。
- `server.debug=true` 才开放 `/api/debug/*`；生产环境应关闭或隔离。

## 3. HTTP REST

### 3.1 服务与注册表

`GET /` 返回 `{"status":"ok","http_port":8080,"ws_port":8081,"debug":true}`。

`GET /api/drones` 返回顶层数组。每条记录包含 `id/id_str/name/model/slot/slot_number/ip/port/video_url/status/battery/x/y/z/yaw/speed/gps_lat/gps_lon/gps_alt/gps_fix/armed/offboard/task_mode/task_state/task_array_id/task_current_wp/task_waypoint_count/task_detail/task_updated_at/ue_receive_port/topic_prefix/bit_index/mavlink_system_id`。

`x/y/z` 是后端 NED→UE 转换后的 cm；`gps_*` 是当前遥测全球位置；`task_*` 是后端任务缓存。状态为 `offline`、`connecting`、`online` 或 `lost`。

`POST /api/drones` 注册一架无人机，请求字段为 `name`、`model`、`slot`/ `slot_number`、`ip`、`port`、`video_url`。slot 必须存在于 1～6 的 `port_map` 且不能重复；`ip/port` 会持久化，但实际控制映射由启动配置的 `port_map[slot]` 决定。成功 HTTP 201 返回 `id/id_str/slot/name`。

`PUT /api/drones/{id}` 可更新 `name`、`model`、`ip`、`port`、`video_url`，当前不更新 slot。
`DELETE /api/drones/{id}` 删除记录和后端运行时上下文。
`GET /api/drones/{id}/anchor` 返回 GPS 上电锚点；无有效锚点返回 HTTP 425。

`POST /api/drones/refresh` 对 `offline/lost` 设备发送安全 hold 探测，返回 `ok/message/refreshed_drone_ids`。空数组表示没有断连设备需要探测；该接口不会直接修改在线状态。

### 3.2 视频元数据

`POST /api/video-metadata/batch` 的请求至少需要 `mission_id`、`drone_id`、非负 `batch_sequence`、对象数组 `frames`；可选 `schema_version`、`final`、`stream_path`、`rtsp_url`、`video_url`、`camera_info`、`summary`、`sent_at_unix_ns`。

`mission_id/drone_id` 必须是安全路径组件；单批上限由 `video_metadata_max_batch` 控制，当前为 300；非 final 批次不能为空。相同 mission/drone/sequence 已存在时返回 `duplicate=true`，不重复追加。结果包含 `accepted_frames`、`completed`、`relative_batch_path`。

### 3.3 阵列任务

`POST /api/arrays` 请求结构：

```json
{
  "array_id": "a1",
  "mode": "scout",
  "auto_assign": false,
  "paths": [{
    "pathId": 1,
    "drone_id": "d1",
    "bClosedLoop": false,
    "waypoints": [{
      "location": {"x": 1000, "y": 0, "z": -500},
      "segmentSpeed": 2.0,
      "waitTime": 0.0
    }]
  }]
}
```

- `mode` 为 `scout`、`patrol`、`attack`；`recon` 归一化为 `scout`。
- `auto_assign=false` 时路径需要 `drone_id`；`true` 时后端从在线无人机匹配路径。
- 兼容 `pathId/path_id`、`drone_id/droneId`、`bClosedLoop/closed_loop`。
- waypoint 坐标是对应执行机本地上电原点下的 UE cm，不是 Cesium 绝对世界坐标。
- `segmentSpeed/segment_speed` 是 m/s，最终归一化到 `[0.5,15]`；0 表示 unlimited marker。
- `waitTime/wait_time` 是秒。

成功 HTTP 201：`{"array_id":"a1","status":"assembling"}`。停止使用 `POST /api/arrays/{id}/stop`，返回 `{"array_id":"a1","status":"stopped"}`。

## 4. WebSocket

连接：`ws://<backend-host>:8081/ws`。

### 4.1 UE → 后端

目标指令必须使用 `mode`：

```json
{
  "mode": "move",
  "drone_id": "d1",
  "x": 1000,
  "y": 2000,
  "z": 500,
  "speed": 2.0,
  "coalesce_queued_vertical_targets": false,
  "coalesce_queued_manual_targets": false,
  "request_id": "req-001"
}
```

`mode` 支持 `move/scout/patrol/attack`；当前实时入口都按目标点移动处理。缺省/0 `speed` 表示兼容旧调用的无限速标记；有限值归一化到 `[0.5,15]`。旧 `{"type":"move"}` 明确返回 400。

暂停/恢复使用 `{"type":"pause"|"resume","drone_id" 或 "drone_ids":...}`。请求携带 `request_id` 且成功时才返回 `command_ack`。

### 4.2 后端 → UE

消息类型：`telemetry`、`event`、`alert`、`assembling`、`assembly_complete`、`assembly_timeout`、`assignment_result`、`drone_task_state`、`command_ack`、`error`。

`telemetry` 字段包括 `drone_id/drone_id_str/x/y/z/yaw/pitch/roll/speed/battery/armed/offboard/gps_lat/gps_lon/gps_alt/gps_fix/local_position_valid/anchor_valid/anchor_gps_*`。`x/y/z` 为 UE cm，姿态为度，速度为 NED velocity 的 m/s 模长，`battery=-1` 表示未知。

`event.event` 为 `power_on`、`lost_connection`、`reconnect`；有效锚点存在时 power_on/reconnect 带 GPS。`alert` 常见类型为 `low_battery`、`lost_connection`，带 `value`。

| type | 关键字段 | 语义 |
|---|---|---|
| `assembling` | `array_id/ready_count/total_count` | 集结进度 |
| `assembly_complete` | `array_id` | 集结完成并启动执行引擎 |
| `assembly_timeout` | `array_id/ready_count/total_count` | 集结超时 |
| `assignment_result` | `array_id/assignments[{path_id,drone_id}]` | 自动分配结果 |
| `drone_task_state` | `drone_id/array_id/mode/state/current_wp/waypoint_count/detail/updated_at` | 后端权威任务状态 |

任务状态：`standby`、`moving`、`assembling`、`scouting`、`patrolling`、`attacking`、`paused`、`avoiding`、`completed`、`error`。`command_ack` 只代表后端接受，不代表机载执行。

## 5. 后端 → Jetson：UDP JSON v1

控制报文根字段：`protocol=ue5_drone_control`、`version=1`、`type=control`、`session_id`、`command_id`、`sequence`、`drone_id`、`slot`、`mode`、`issued_at_unix_s`、`sent_at_unix_s`、`target`、`delivery`；有限速度时另有数值 `speed`，无限速时为字符串 `"NaN"`。

`target` 固定为 `{"frame":"NED","reference":"power_on_origin","unit":"m","north":...,"east":...,"down":...}`。
`delivery.repeat_index` 从 1 开始，move 默认 `repeat_total=5`，持续 hold 为 0。

后端默认以 5Hz 重发 move 5 次；Jetson 默认在 2.5 秒内收到 3 个不同 `repeat_index` 且负载一致的包才应用。旧 session/sequence、错误 slot、重复索引或负载冲突必须拒绝。

## 6. Jetson → 后端：UDP YAML

后端解析：`timestamp`、`position[N,E,D]`、`q[w,x,y,z]`、`velocity`、`angular_velocity`、`local_position`、`local_position_valid`、`gps_lat/gps_lon/gps_alt/gps_fix`、`arming_state`、`nav_state`、`battery`、`control_ack`。

有效 `local_position_valid=true` 且数组存在时，后端用 `local_position` 作为内部 NED 位置。`q` 顺序为 `[w,x,y,z]`；`nav_state=14` 派生为 offboard，`arming_state=2` 派生为 armed。 `control_ack` 包含 `session_id/command_id/sequence/mode/confirmed_packets`，是应用层 ACK，不是 UDP 收包 ACK。

## 8. 版本边界

- 当前控制协议是 JSON v1，不是旧 24 字节二进制结构体。
- 后端和 Jetson bridge 必须成套升级；旧 bridge 不能直接解析当前 JSON 控制。
- `speed`/`segmentSpeed` 的后端链路已实现，但 Jetson 是否在真实飞行中采用速度 setpoint 仍需实机验收。
- 文档中的 `BackEnd` 路径、旧 Python bridge、旧端口和旧字段都应回到源码核对。
