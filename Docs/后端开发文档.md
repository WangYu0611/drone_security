# 后端开发文档（当前实现）

> 更新时间：2026-09-09
> 事实来源：`Backend/` 当前源码和 `Backend/config.yaml`。历史需求表不作为接口契约。
> 运行结论边界：源码存在、单元测试通过、后端 UDP 发送成功、WebSocket `command_ack`，都不能单独证明 Jetson/PX4 已执行；机载应用确认必须看 YAML `control_ack`。

## 1. 职责和拓扑

```text
UE5
 ├─ HTTP REST :8080 ───────────────┐
 ├─ WebSocket :8081/ws ────────────┤
 │                                 ▼
 │                         DroneBackend
 │                   ┌──────┴─────────┐
 │                   │ HTTP / WS      │
 │                   │ DroneManager   │── UDP JSON v1 ──► Jetson/PX4 bridge
 │                   │ Heartbeat      │◄─ UDP YAML      ── Jetson/PX4 bridge
 │                   │ Assembly       │
 │                   │ Execution      │
 │                   └─────────────────┘
 │
 └─ browser WebRTC `video_url` ─────► MediaMTX（独立视频链路）
```

后端拥有事实和安全边界：注册表持久化、slot/端口映射、连接状态、GPS 锚点、NED 坐标、每机队列、重发、集结、航点执行和基础避障。Jetson/PX4 桥接程序不在当前仓库中，真实机验证必须使用匹配 JSON v1/YAML 协议的外部版本。

## 3. 构建和运行

从仓库根目录运行，保证相对路径指向 `Backend/data/drones.json` 和 `logs/backend.log`：

```powershell
.\Backend\build_simple.bat
.\Backend\build\Release\DroneBackend.exe .\Backend\config.yaml
```

手动构建：

```powershell
cmake -S Backend -B Backend\build -G "Visual Studio 17 2022" -A x64 `
  -DCMAKE_TOOLCHAIN_FILE=C:\dev\vcpkg\scripts\buildsystems\vcpkg.cmake
cmake --build Backend\build --config Release --target DroneBackend
```

默认监听：HTTP `0.0.0.0:8080`，WebSocket `0.0.0.0:8081/ws`。配置、路径和参数以 `Backend/config.yaml` 为准；改配置后需要重启进程。

## 4. REST 接口

错误主体当前主要是 `{"detail":"..."}`，调用方不要假定所有错误都有 `error` 字段。

### 正式接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 服务状态、HTTP/WS 端口和 debug 状态 |
| GET | `/api/drones` | 顶层数组：注册信息、连接/遥测/任务快照 |
| POST | `/api/drones` | 注册无人机；slot 必须是 1～6 且唯一，后端分配 `dN` |
| PUT | `/api/drones/{id}` | 更新 name/model/ip/port/video_url；当前不更新 slot |
| DELETE | `/api/drones/{id}` | 删除注册记录和运行时上下文 |
| GET | `/api/drones/{id}/anchor` | 获取有效 GPS 上电锚点；无锚点返回 HTTP 425 |
| POST | `/api/drones/refresh` | 对 offline/lost 设备发送安全 hold 探测，不直接改在线状态 |
| POST | `/api/video-metadata/batch` | 幂等保存视频元数据 JSONL 批次 |
| POST | `/api/arrays` | 创建集结/阵列任务，成功返回 `201` 和 `array_id` |
| POST | `/api/arrays/{id}/stop` | 停止阵列和执行引擎 |

### Debug 接口

仅 `server.debug=true` 时开放：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/debug/drone/{id}/state` | 状态、遥测、队列/心跳摘要、最近 ACK |
| GET | `/api/debug/drone/{id}/queue` | 当前控制目标队列 |
| GET | `/api/debug/heartbeat/{id}` | 发送/失败/重发统计 |
| POST | `/api/debug/drone/{id}/inject` | 注入一帧模拟遥测 |
| POST | `/api/debug/cmd/{id}/move` | 注入 UE cm 目标，可带 `speed` |
| POST | `/api/debug/cmd/{id}/pause` | 暂停并 hold |
| POST | `/api/debug/cmd/{id}/resume` | 恢复队列 |
| POST | `/api/debug/cmd/{id}/array` | 单机任务调试 |
| POST | `/api/debug/cmd/batch/array` | 多机任务调试 |
| POST | `/api/debug/cmd/{id}/target` | 注入目标识别事件 |
| GET | `/api/debug/arrays/{id}/state` | 查看阵列状态 |

## 5. WebSocket

连接地址：`ws://<backend-host>:8081/ws`。

UE → 后端的目标点必须使用 `mode`：

```json
{"mode":"move","drone_id":"d1","x":1000,"y":2000,"z":500,"speed":3.0}
```

`mode` 为 `move`、`scout`、`patrol`、`attack`；`recon` 只在后端输入归一化为 `scout`。`x/y/z` 是目标机本次上电原点下的 UE 相对偏移，单位 cm。`speed` 是 m/s；0/非有限值表示无限速兼容标记，有限值会归一化到 `[0.5,15]`。旧 `{ "type":"move" }` 不再是有效目标请求。

暂停/恢复：

```json
{"type":"pause","drone_ids":["d1","d2"]}
{"type":"resume","drone_id":"d1","request_id":"req-2"}
```

后端可能推送：`telemetry`、`event`、`alert`、`assembling`、`assembly_complete`、`assembly_timeout`、`assignment_result`、`drone_task_state`、`command_ack`、`error`。`command_ack` 只表示后端接受/入队；YAML `control_ack` 才表示 Jetson 达到应用确认阈值。

## 6. UDP 协议和端口

### 6.1 后端 → Jetson：JSON v1

控制报文包含 `protocol=ue5_drone_control`、`version=1`、`type=control`、`session_id`、`command_id`、`sequence`、`drone_id`、`slot`、`mode`、时间戳、`target` 和 `delivery`。`target` 固定声明：

```json
{"frame":"NED","reference":"power_on_origin","unit":"m","north":10.0,"east":20.0,"down":-5.0}
```

move 默认用同一逻辑命令重发 5 次，`delivery.repeat_index` 从 1 开始；持续 hold 的 `repeat_total` 为 0。速度为有限数值时传数字，无限速兼容值在下游协议中为字符串 `"NaN"`。

### 6.2 Jetson → 后端：YAML

当前解析字段包括 `timestamp`、`position`、`local_position`、`local_position_valid`、`q`、`velocity`、`angular_velocity`、`battery`、`gps_lat/gps_lon/gps_alt/gps_fix`、`arming_state`、`nav_state` 和 `control_ack`。有效 `local_position` 才用于控制/到达判断。

`control_ack` 至少包含 `session_id`、`command_id`、`sequence`、`mode`、`confirmed_packets`，可带 `applied_at_unix_s`。

### 6.3 slot 端口

| slot | 遥测接收 | 控制发送 |
|---:|---:|---:|
| 1 | 8888 | 8889 |
| 2 | 8890 | 8891 |
| 3 | 8892 | 8893 |
| 4 | 8894 | 8895 |
| 5 | 8896 | 8897 |
| 6 | 8898 | 8899 |

实际控制目标 IP 优先使用 `port_map.<slot>.host`。注册请求的 `ip/port` 会持久化并返回，但不会替代启动时的 slot 映射。

## 7. 任务执行和不变量

- `POST /api/arrays` 进入集结；后端按路径和目标机建立任务，推送 `assembling`，全部满足到达阈值后推送 `assembly_complete` 并启动执行。
- 集结超时默认 60 秒，推送 `assembly_timeout`，相关任务状态转为 error。
- `scout`、`patrol`、`attack` 共享航点执行基础设施；patrol 可处理目标事件，attack 到末点后不循环，具体状态以 `drone_task_state` 为准。
- 基础避障参数默认安全距离 3 m、前视 2 s；这不是全局路径规划。
- 失联超时默认 10 秒。重新上电可能产生新的 NED 原点，后端清理旧坐标目标，避免旧目标在新原点下重放。
- 每架机的上电 NED 原点独立。阵列进入后端前必须完成每条路径相对目标机的原点补偿。

## 8. 最小验证

```powershell
curl.exe http://127.0.0.1:8080/
curl.exe http://127.0.0.1:8080/api/drones
cmake --build Backend\build --config Release --target DroneBackend_tests
.\Backend\build\Release\DroneBackend_tests.exe
```

无真实无人机时使用 `/api/debug/drone/{id}/inject` 和 `tools/mock_ue/`；它们只能证明后端解析、状态和协议路径。真实 Jetson/PX4、跨机网络、UE 5.7 Play Mode、Cesium 对齐和 WebRTC 播放必须分别记录运行证据。
