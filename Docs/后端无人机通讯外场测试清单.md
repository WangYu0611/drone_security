# 后端与无人机通讯外场测试清单（当前协议）

> 更新时间：2026-09-09
> 适用：UE5DroneControl 当前 `Backend/` C++17 服务、外部 Jetson/PX4 bridge、UE 5.7。
> 安全边界：无桨/固定台测试不得解锁或起飞；真实飞行必须另有符合场地和法规的飞行检查单。
> 证据规则：每一项记录命令、时间、设备/slot、原始日志或响应。HTTP 2xx、UDP send 成功和 WS `command_ack` 不能代替 `control_ack`。

## 1. P0：版本、配置和安全

- [ ] 后端使用当前 `Backend/` 构建产物；不要使用旧的 `BackEnd` 目录、旧 Python 后端或 24 字节二进制控制程序。
- [ ] Jetson bridge 明确支持 `protocol=ue5_drone_control`、JSON v1、`target.frame=NED`、`reference=power_on_origin`、YAML `control_ack`。
- [ ] 真实飞行前完成拆桨/固定、急停、失联、人工接管和空域检查。
- [ ] 确认 `Backend/config.yaml` 的 `port_map.<slot>.host`、控制端口和接收端口；注册表中的 `ip/port` 不是启动映射的替代品。
- [ ] 确认后端 `server.debug`：模拟注入可开，生产/外场按安全策略关闭或隔离 debug 路由。
- [ ] 确认本次后端从仓库根目录启动，避免相对路径误指向其他数据目录。

当前默认参数：`HTTP=8080`、`WS=8081/ws`、`heartbeat_hz=5`、`command_repeat_count=5`、`lost_timeout_sec=10`、`arrival_threshold_m=1.0`、`assembly_timeout_sec=60`、`avoidance_radius_m=3.0`。

## 2. P1：后端本地健康检查（无无人机）

从 `D:\RedAlert\UE5DroneControl` 执行：

```powershell
.\Backend\build_simple.bat
.\Backend\build\Release\DroneBackend.exe .\Backend\config.yaml
```

另开终端：

```powershell
curl.exe http://127.0.0.1:8080/
curl.exe http://127.0.0.1:8080/api/drones
```

通过条件：

- [ ] `GET /` 返回 `status=ok`、HTTP/WS 端口和 debug 状态。
- [ ] `GET /api/drones` 返回顶层 JSON 数组。
- [ ] `logs/backend.log` 和终端显示服务已监听；没有端口绑定或配置加载错误。
- [ ] 记录实际响应，不把历史日志当作本次通过证据。

C++ 单元测试：

cmake --build Backend\build --config Release --target DroneBackend_tests

## 3. P2：注册表和 slot

```powershell
curl.exe -i -X POST http://127.0.0.1:8080/api/drones `
  -H "Content-Type: application/json" `
  -d '{"name":"UAV1","model":"PX4","slot":1,"ip":"192.168.30.103","port":8889}'

curl.exe http://127.0.0.1:8080/api/drones
curl.exe -i -X POST http://127.0.0.1:8080/api/drones `
  -H "Content-Type: application/json" `
  -d '{"name":"UAV1-duplicate","slot":1}'
```

- [ ] 首次注册为 HTTP 201，响应包含 `id`、`id_str`、`slot`。
- [ ] 列表中 `id/id_str/slot/status` 和端口摘要符合配置。
- [ ] 重复 slot 被拒绝；记录真实 HTTP 状态和 `detail`。
- [ ] 更新只改允许字段，不能把 PUT 当成改 slot 接口。
- [ ] 删除后运行时上下文和持久化记录均清理；如需重跑，显式执行 `DELETE /api/drones/{id}`。

## 4. P3：WebSocket 观察和后端注入

连接：

```powershell
wscat -c ws://127.0.0.1:8081/ws
```

如果使用 `tools/mock_ue/`，按其 README 安装依赖和启动命令；不要把 mock 输出作为真实飞控证据。

注入一帧遥测：

```powershell
curl.exe -i -X POST http://127.0.0.1:8080/api/debug/drone/1/inject `
  -H "Content-Type: application/json" `
  -d '{"position":[1,2,-3],"q":[1,0,0,0],"velocity":[0,0,0],"battery":85,"gps_lat":39.9,"gps_lon":116.3,"gps_alt":50,"gps_fix":true,"local_position":[1,2,-3],"local_position_valid":true}'
```

- [ ] WS 收到 `telemetry`，其中相对 UE 偏移为 `x=100,y=200,z=300` cm。
- [ ] 首个有效 GPS 后收到 `event/power_on`，并可查询 `/api/drones/1/anchor`。
- [ ] 注入 `battery < low_battery_threshold` 时收到 `alert`；恢复后不重复刷屏。
- [ ] `GET /api/debug/drone/1/state` 的 `local_position_valid`、状态和最近 ACK 可解释。

该阶段只验证后端处理链，不证明真实 UDP、Jetson 或 PX4。

## 5. P4：后端到 Jetson 的 UDP 控制

先确认 Jetson bridge 在对应 slot 的控制端口监听，并记录两端 IP/端口。抓包过滤示例：

```text
udp.port == 8888 || udp.port == 8889
```

移动目标：

```powershell
curl.exe -i -X POST http://127.0.0.1:8080/api/debug/cmd/1/move `
  -H "Content-Type: application/json" `
  -d '{"x":1000,"y":2000,"z":500,"speed":3.0}'
```

应在后端/抓包/Jetson 日志中分别记录：

- [ ] WS/HTTP 调试入口接受的是 UE cm 相对目标。
- [ ] 后端队列或 debug state 显示 NED 目标约为 `(10,20,-5)m`。
- [ ] UDP 报文是 JSON v1，包含 session、command、sequence、slot、NED target 和 delivery，而不是 `<dfffI` 二进制包。
- [ ] 同一 move 的重复索引和 `repeat_total=5` 符合当前配置。
- [ ] Jetson 记录 JSON 校验、去重和 `3-of-5` 应用过程。
- [ ] Jetson 回传 YAML `control_ack`，其中 `session_id/command_id/sequence` 与该指令一致。
- [ ] 只有完成上一步，才可把本项标记为“机载应用确认”。

`command_ack` 或后端 `sent_count` 只能记为“后端接受/已尝试发送”。

## 6. P5：WebSocket 控制和暂停恢复

向 wscat 发送当前协议：

```json
{"mode":"move","drone_id":"1","x":1000,"y":0,"z":500,"speed":2.0,"request_id":"move-1"}
{"type":"pause","drone_ids":["1"],"request_id":"pause-1"}
{"type":"resume","drone_ids":["1"],"request_id":"resume-1"}
```

- [ ] `mode` 必须是 `move/scout/patrol/attack`；旧 `{"type":"move"}` 应被拒绝。
- [ ] 目标进入指定 slot 的队列，暂停会生成 hold，恢复后队列可继续。
- [ ] 能区分 WS `command_ack` 和 YAML `control_ack`。
- [ ] 暂停/恢复期间的机载安全状态由现场负责人确认；无 ACK 时不得继续飞行测试。

## 7. P6：连接状态和重连

- [ ] 停止某 slot 的 YAML 遥测，等待配置的 10 秒超时。
- [ ] `GET /api/drones` 状态进入 lost，WS 收到 `event/lost_connection` 和相应告警。
- [ ] 恢复遥测并使用新的有效 GPS/本地位置。
- [ ] WS 收到 `event/reconnect`，锚点被更新；后端清理旧上电原点下的控制目标。
- [ ] 重新发出的第一条目标使用新 `session_id`/sequence 语义，不能重放旧原点目标。

## 8. P7：UE ↔ 后端

修改 `Config/DefaultGame.ini` 后启动 UE 5.7：

- [ ] `UDroneNetworkManager` 日志显示实际 `BackendBaseUrl` 和 `/ws` 地址。
- [ ] 轮询约每 3 秒发生一次 `GET /api/drones`。
- [ ] WS 连接成功；遥测进入 Registry，镜像 Actor/UI 更新。
- [ ] 地图点击发送的坐标是世界坐标减去目标机锚点后的相对 cm。
- [ ] 进入严格本地预演后，轮询、WS 和所有后端写请求都停止；UI 显示隔离提示。
- [ ] 关闭隔离后 WS、轮询和一次立即同步恢复。

如果只使用 UE 本地路径预演，明确记录“未连接后端”，不能用影子机动画证明真机控制。

## 9. P8：阵列、集结和任务状态

- [ ] UE `POST /api/arrays` 请求使用 `mode=scout/patrol/attack`、路径和 waypoint 字段。
- [ ] `auto_assign=true` 时路径 `drone_id` 为空，收到 `assignment_result` 后 UI 重新绑定。
- [ ] WS 按顺序收到 `assembling`，全部到位后收到 `assembly_complete`；超时路径收到 `assembly_timeout`。
- [ ] `drone_task_state` 的 `array_id/mode/state/current_waypoint` 与后端状态一致。
- [ ] patrol 的目标事件、attack 的末点不循环、scout 的闭环语义分别记录。
- [ ] 多机阵列每条路径均按执行机的 GPS/上电 NED 原点换算；在此项未通过前不得进行外场阵列飞行。
- [ ] 用 `POST /api/arrays/{id}/stop` 验证停止后不再派发新目标，UE 清理本地预演路径。

## 10. P9：视频与元数据（独立验收）

MediaMTX 当前本地演示：RTSP `8554`、WebRTC 页面 `8889`、ICE UDP `8189`，路径 `drone-1`/`drone-2`/`drone-3`。可运行：

```powershell
.\tools\MediaMTX\start_demo_streams.cmd
```

- [ ] 浏览器能打开 `http://127.0.0.1:8889/drone-1` 并播放。
- [ ] UE 读取 `/api/drones` 的 `video_url` 后能打开同一浏览器页面。
- [ ] 关闭 UE 视频窗口会导航到 `about:blank`，不把这一步误判为 MediaMTX 停止。
- [ ] 若测试视频元数据，确认 `Backend/config.yaml` 的 `storage.video_metadata_path` 和 `/api/video-metadata/batch` 结果。

视频播放成功不证明控制链路、GPS、SfM 或 PX4 执行成功。
