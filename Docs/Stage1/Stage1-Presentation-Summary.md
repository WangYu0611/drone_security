# 项目目标

建设一个面向无人机安防业务的可视化指挥系统，让操作人员在同一工作台完成安保方案编制、无人机分配、地图航线规划、任务部署与执行监控，同时集中查看视频、告警和业务记录。

**Stage 1 已完成软件业务的 Mock 执行闭环，可以进行有条件的正式演示。真实无人机接口基础保留，尚未作为当前 Stage 1 执行链重新验收。**

本稿依据 2026-09-20 源码审计及仓库已有验收证据。“已验证”指已保存的测试/原生操作记录，本轮仅审计，不表示当天重跑。

# Stage 1 当前系统能力

## 系统架构【已验证】

一台电脑运行 Backend、Command、Map、Video 四个独立进程。Backend 统一管理业务状态；Command 负责操作；Map 负责地理信息和航线；Video 负责视频目标和播放界面。Launcher 提供启动、窗口聚焦、排列、单独重启及统一关闭。

## 无人机管理【已验证：软件与 Mock 范围】

系统通过 UAV Registry 统一管理无人机身份、选择、状态和任务关联。当前演示配置含四架明确标识的 Mock UAV。当前选中无人机、任务分配无人机、正在执行任务和视频目标相互独立。

Mock 的业务可用性不代表真实遥测 Online，也不代表电量、GPS 或飞控已经接通。

## 地图与地理信息【当前可用；影像和 3D 存在条件】

Map 客户端保留 Cesium 地理场景、2D/3D 切换、缩放、平移、定位、航点编辑与执行航线显示。执行时可查看已完成、当前和待执行航点，以及无人机在地图上的位置。

当前演示应使用 Map 客户端。早期 Command 内嵌 2D tactical map 的代码仍保留，但当前 Command 页面没有创建该控件。在线影像可用性和低高度地形遮挡需要提前检查。

## 坐标转换【当前可用；真机高度基准需复核】

工程保留 WGS84 地理坐标与 UE 世界坐标的双向转换，并保留 NED 米与 UE 厘米换算、GPS 锚点及栅格 WGS84/GCJ-02 转换。

真实无人机高度、地图椭球高、相对地面高度不是同一概念。接回真实无人机时需核实高度基准、大地水准面差和本地坐标原点。

## 安保方案【已验证】

支持新建、列表浏览、打开、复制为草稿和草稿删除；方案分为草稿、准备就绪、已部署。已部署方案只读，复制后的新方案拥有独立任务和航线，保留原部署记录。

## 任务规划【已验证】

新建方案可自动生成任务，操作人员分配无人机后进入 Map 编辑航线。Save 保存后继续编辑，Finish 结束编辑并回到部署检查，避免把“已保存”误解为“已结束规划”。

## 任务部署【已验证】

部署前检查任务、无人机分配、路线和修订状态；人工复核通过后形成不可变部署快照。**部署不等于开始执行。**

## 任务执行【已验证：Mock】

显式 Start Mission 后，Backend 推进模拟任务，并同步位置、当前航点、进度和时长。支持暂停、继续、模拟返航、中止、正常完成及失败记录；同一无人机不能同时被两个活跃执行占用。

返航是返回已配置的模拟 Home，不是已接通真实飞控 RTL。已有四航点原生完成记录约 150 秒，可用于安排演示节奏。

## 实时状态【已验证：软件同步】

Command 与 Map 使用同一 Backend 执行快照。客户端重启可重新获取任务状态，业务不会因仅关闭展示窗口而自动丢失。Mock 更新目标为 10 Hz；已有短时观测约 9.18 Hz，不作为严格实时或容量指标。

## 视频【界面已验证；当前媒体源需准备】

Video 支持明确选择视频目标、主画面、4/6 卡片布局、Focus、主副卡切换、重试与空态反馈。当前只有一个实际播放器，其余卡片为预留入口，不能宣传为 4/6 路同时播放。

当前保存的 Mock UAV 视频地址为空。演示可以展示视频布局与目标隔离；若需播放，应提前准备并标识经过检查的演示源。历史 RTSP/WebRTC 链路保留，本轮未重接真实相机。

## 告警与日志【已验证：已有场景】

Command 提供告警列表和操作日志。业务事件来自 Backend，再投影到客户端；支持查看方案、部署、执行及连接相关记录。本地清理显示不删除 Backend 业务历史。Alert 已处理状态属于当前会话，不应宣传为已交付完整持久告警工单系统。

## 中英文【已验证：主流程；旧界面部分待补齐】

Command、Map、Video 通过共享语言偏好同步 en/zh-Hans。切换语言不会修改方案、执行航线或视频目标。旧地理坐标输入和部分工具仍有固定语言文字。

## 数据持久化【已验证：业务记录】

方案、任务、路线、部署快照、执行历史、共享选择和语言偏好由 Backend 保存。Launcher 首次初始化演示数据时不会覆盖已有记录。视频目标单独保存；未设置时可以保持默认空态。

## 系统恢复【已验证：已有原生场景】

单独重启 Command 或 Map 后，可恢复当前业务状态。Backend 重启从最近保存位置继续模拟；统一关闭先持久暂停，重开后需明确 Resume，避免混淆“重启”和“主动继续任务”。

## 原真实无人机接口基础【历史能力】

保留 Backend UDP 遥测与 JSON 控制、Jetson ROS 2/PX4 桥、GPS/local position 映射、旧航线执行引擎、视频转流与采集元数据接口。历史日志存在 UDP 接收、GPS 锚点、连接变化和命令发送记录。

历史真机联通不等于当前所有控制动作通过验收，也不等于 Stage 1 的 Start 已连到飞控。相机取图的历史成功记录也不能替代当前相机到 UE 的完整播放验证。

## Stage 2 扩展能力【预留方向】

可以基于现有接口推进真实无人机重新接入、业务执行与飞控适配、真实多路视频及多主机部署。仍需完成设备身份、协议版本、坐标高度、控制确认和执行反馈的逐项映射与验证。AI 等扩展尚不属于 Stage 1 已交付能力。

# 汇报时必须保留的边界

- 已保存 Backend 回归为 77 项、75 通过、2 项旧规划器失败；不能表述为全部回归通过。
- UE 最终定向检查为 7 项 SucceededWithWarnings；Cesium 网络、插件及旧失败记录保留。
- 原生软件闭环证据覆盖 P5.2 A–U；本次未重新运行，也未进行飞行验收。
- 当前演示前须检查媒体源、地图加载和已有暂停任务；演示数据本轮没有修改。

# 四个核心问题的回答

| 问题 | 可用于汇报的回答 |
|---|---|
| Q1 当前可以做什么？ | 单机三客户端协同完成方案、分配、地图航线、部署、显式开始、Mock 执行监控与恢复。 |
| Q2 哪些旧能力保留？ | Cesium/坐标转换/Registry/HTTP/WS、旧路径工具、UDP遥测控制、ROS2 PX4桥、视频/元数据基础；当前启用程度各不相同。 |
| Q3 真机接回用哪些接口？ | Jetson UDP YAML 遥测、Backend UDP JSON v1 控制、ROS2 px4_msgs、RTSP/MediaMTX WebRTC；还需把当前 Execution 业务适配到旧控制反馈链。 |
| Q4 哪些已验证，哪些仅历史？ | Mock软件闭环有保存的自动化与原生证据；真机遥测/相机部分有历史记录，当前真实飞行和真实视频全链未重验。 |
